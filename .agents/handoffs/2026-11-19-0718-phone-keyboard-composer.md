## Goal

On the phone app (Android APK, `apps/app`), the software keyboard must not cover the message composer. Done when the composer stays visible above the keyboard while typing in a thread, and the owner has seen it on a phone.

## State

- **Cause (verified by reading):** Expo apps are edge-to-edge on Android. `android/gradle.properties` (generated by prebuild, git-ignored) sets `edgeToEdgeEnabled=true`, so the window no longer resizes for the keyboard, and the manifest's `adjustResize` has no effect. Expo's keyboard guide says: "A view without a `behavior` stays under the keyboard." RN's `ReactRootView` emits `keyboardDidShow` with `endCoordinates.height` from the IME insets on Android (read in `node_modules/react-native/ReactAndroid/src/main/java/com/facebook/react/ReactRootView.java`).
- **Fix (built, uncommitted at the time of writing):** `apps/app/src/foundation/keyboardHeight.ts` adds `useKeyboardHeight()`, which listens to `keyboardDidShow`/`keyboardDidHide` on Android and `keyboardWillShow`/`keyboardWillHide` on iOS. `apps/app/App.tsx` gives the outermost view `paddingBottom: keyboardHeight`, which is the resize `adjustResize` used to do. No new dependency.
- **Checks run now:** `bunx biome check` on both files: clean. `bun run typecheck` in `apps/app`: clean. `CI=1 bunx vitest run apps/app`: 75 files, 550 passed, 6 skipped.
- **Not verified:** not run on a phone or in an emulator; no APK built from this change. The composer's position above the keyboard is assumed from the code, not seen.
- **Known gaps:** the add-host dialog (`apps/app/src/shell/addHostModal.tsx`) is a React Native `Modal`, a separate Android window that this padding does not reach; its text fields may still be covered. The web app in a phone browser was not checked. iOS is not shipped and its path is untested.
- **Working tree at the time of writing:** `apps/app/App.tsx` modified and `apps/app/src/foundation/keyboardHeight.ts` new. Nothing else from this thread.
