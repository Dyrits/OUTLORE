## Goal

The release tag's workflow also builds an Android APK of the same Expo app, so there is a mobile app and not only the browser one. Done means a tag publishes `Outlore-<version>-android.apk` in the release, and an owner can install it, pair it with a host and use quests.

## Decisions

- The owner took the recommendations: pipeline and code adapted for Android; `expo prebuild` and Gradle, no EAS; release keystore in repository secrets; the APK in the GitHub release (journal entry 1; ADR 0009 amended).
- One APK for arm64-v8a only (speed and size); an emulator on an Intel machine would need `x86_64` added in the workflow.
- A manual **Run workflow** without secrets signs with the debug key and names the file `...-android-debug-signed.apk`; a tag never does.
- The AskUserQuestion dialog did not display in this app (a debug thread found Outlore allows it without asking), so questions went in plain text.
