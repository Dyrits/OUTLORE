# Changelog: 0.1.13-Prototype

## CHG-0559 · 2026-11-20 · Codex turns failed with "failed to load workspace requirements: invalid input parameter"

Type: Fix
Event: Delivery
Scope: `packages/service` (Codex harness, the Vault's permission profile)

Summary: Every Codex turn failed once the Vault's folder was hidden from Codex's sandbox (ADR 0022). `thread/start` took the profile's definition (`permissions.outlore.*`) in its `config`, but a turn reloads Codex's settings without that thread's overrides, finds no profile named `outlore`, and fails with that message after five retries. Reproduced with a direct `codex app-server` session on Codex 0.170.0: the `outlore` profile fails, `workspace-write` and the built-in `:workspace` profile pass.
- The profile is now defined on the process: `codex app-server -c default_permissions="outlore" -c permissions.outlore.…`, and `thread/start` only names it. A profile in the process settings needs `default_permissions`, or Codex refuses to start.
- The same session with those arguments answers a turn. The deny rule itself is the one `readDenial.test.ts` already probes with `codex sandbox`.
Reason: The owner's screenshot of the failed turn. The 2026-11-19 verification had tried `thread/start` and `codex sandbox` but "no live Codex turn was run".
Validation: Direct app-server session (profile in `thread/start`: turn fails; profile in startup arguments: turn answers "ok"); `adapterDenial.test.ts` passes (10 tests); `bun run typecheck` passes. Not checked: the full suite, and a turn from the Outlore window.

## CHG-0554 · 2026-11-19 · Conversation panes: realms are channels, one card per errand, no prototype

Type: Documentation
Event: Agreement
Scope: Conversation panes

Summary: The owner's second round of comments on CHG-0553 settles:
- Realms are channels: each has its own main conversation in which its quests unfold, and the Borderlands is one more channel. The app-wide main conversation is the overview that logs everything happening (a realm opens, a quest opens, and so on); its name is open ("Quest log", "Log", or a name that fits the overview; the specification says "the Log" meanwhile).
- Chronicler answers in every channel, its Companion settable as everywhere; in a realm's channel it has that realm's memory, in the Borderlands only the global memories.
- `@` is kept as it is; `#` is not built, and telling a citation from a channel reference waits for multiplayer.
- An errand has one card of its own, a system message with its title like today's "errand opened" message, never several under one message; the card is its reply line.
- When the chain is longer than four panes, the last four show and earlier ones fold to strips.
- No throwaway prototype: the layout is built directly in a worktree, and the feel is judged on it.
Reason: The owner's comments.
References: [Specifications](../capabilities/conversation-panes/specifications.md), [draft](../capabilities/conversation-panes/draft.md), CHG-0553.
Validation: The owner's comments of 2026-11-19 on the Companion's questions, in the thread of this quest. Not built, so not verified.

## CHG-0554 · 2026-11-19 · A connector's key is entered in its own panel, not in the Vault tab

Type: Code
Event: Agreement and Delivery
Scope: `apps/app` (settings, connectors), `packages/service` (connector card wording)

Summary: Asked whether the Composio key is set in the Composio tab, I said it was entered in the Vault tab, with only a button leading there. The owner answered that it has to be in the connector's tab, and that the Vault is for other secrets, such as passwords for browsing online.
- The Connection block of a connector's panel holds a field for each kind of secret the connector needs (Composio: API key): add, replace or remove it, with its stored state. The field is the Vault's own (`SecretField`, moved out of `vaultCard.tsx`); the value goes to the service once and is never read back.
- When the Vault refuses to store (its read-denial rule, a locked or lost key), the panel shows the Vault's reason and a button to the Vault tab, where Claude Code's protection is verified. The rule is unchanged.
- The Vault tab keeps its state, protection and verification, and lists only the secrets no panel holds: those of a connector that is not installed or is being removed, so they can still be removed. `leftBehindOf` decides it.
- Composio's card says "Add your API key below." instead of "in the Vault."
- Not done: a store for secrets that belong to no connector (passwords for browsing online). The service's `PutSecret` takes a connector id and a kind, and the specification has no such secret yet; it needs its own agreement before it is built.
Reason: The owner's request.
References: [specification](../capabilities/connectors/specifications.md#the-vault), ADR 0022, CHG-0551.
Validation: Biome clean; `bun run typecheck` passes on all workspaces; the connector, contract and app tests pass (103 files, 789 passed, 7 skipped), with a new test of `leftBehindOf`. Not seen in a window, and no key was stored.

## CHG-0552 · 2026-11-19 · A black and white theme

Type: Code
Event: Agreement and Delivery
Scope: `apps/app` (foundation, settings), `apps/desktop` (app icon), glossary

Summary: The owner asked for a black and white theme. The Workshop's Look card now offers Black & white beside One and Iskios, in a dark look (white on black) and a light look (black on white).
- The palette (`monoPalettes.ts`) holds only greys: surfaces step lighter or darker, the accent is the text color itself, and the state colors (danger, success, warning, violet) differ by a step of grey, so a state is told by its label and icon, not by color.
- The theme is `mono` in code (`Theme`, `themes`, `palettes`, the desktop's `iconFiles`) and "Black & white" in the picker. It keeps the original application icon. A stored selection is read as before; nothing is migrated.

Reason: The owner's request.
References: [glossary](../glossary.md), CHG-0285 (the themes' first form).

## CHG-0551 · 2026-11-19 · Each connector has its own panel in the Workshop, and Apple apps is renamed "Apple's applications on macOS"

Type: Code
Event: Agreement and Delivery
Scope: `apps/app` (settings), `packages/service` (connector catalog and messages)

Summary: The owner compared the Workshop's Connectors section (one long card with every connector's switches and tools stacked, then the Vault, the Borderlands and Code Mode) with OpenBot's per-connector page for Composio, called theirs awful, and asked for at least a dedicated panel for each connector, even without all the options. They then asked for Apple apps to be renamed "Apple's applications on MacOS".
- The Connectors section is now a row of tabs: one per connector the catalog offers, then "The Vault" and "Borderlands". Each connector tab shows only that connector's panel.
- A connector's panel holds: its name and state, its description, Connection (what it needs, an "Open the Vault" button when it needs a secret, the install flow when not installed), Availability (the "On everywhere" switch), Apps (Apple's applications only: which apps, macOS permission, the request button), Tools (grouped, each with its switch and whether it asks first), and a Danger zone (Remove, behind its warning).
- The Borderlands tab holds the placement choices and the Code Mode card, which is now titled "Code Mode" (it was a second card titled "Connectors").
- The connector's display name is "Apple's applications on macOS" in the catalog and in the messages that name it. I wrote "macOS", Apple's own spelling, where the owner wrote "MacOS"; the connector's id (`apple`) is unchanged, so nothing stored or granted is affected.
- Not done: OpenBot's header with prompt suggestions, role and agent access, an information table. Nothing in Outlore yet backs them.
- Replaced `settings/connectorsCard.tsx` by `connectorsSection.tsx`, `connectorPanel.tsx` and `connectorPanelBlocks.tsx`; the toggle, request and removal logic moved unchanged.
Reason: The owner's request, with the screenshots of both menus.
Validation: Biome clean; `bun run typecheck` passes on all workspaces; the connector, contract and app tests pass (103 files, 788 passed, 7 skipped). The full suite has 6 failing files (28 tests: worktrees, folder picker, own copies, workspace entries) that all stop at `git init` copying hook templates into a folder the thread's sandbox cannot write; they are not touched by this change and run on the owner's machine.
