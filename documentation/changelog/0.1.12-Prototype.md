# Changelog: 0.1.12-Prototype

## CHG-0527 · 2026-11-19 · A quest's header: Mark as done and a quest icon; the panel's edge handle goes

Type: Code
Event: Agreement and Delivery
Scope: `apps/app` (`conversation/conversation.tsx`, `ui/questHeaderButtons.tsx`, `shell/shell.tsx`, `shell/questTab.ts`, `foundation/shellContext.tsx`)

Summary: At the right of an open quest's title and dot, the header now reads Archive, Mark as done, a vertical separator, and the quest icon (the sword without the plus). Mark as done is a checkbox: pressing it marks the quest done (with the existing confirmation when threads are at work), pressing it again, now ticked, reopens the quest. The quest icon opens the right-hand column on its Quest tab, also from the Companions tab, stays filled while that tab shows, and closes the column when pressed again. The round handle on the column's edge is left out while a quest is open; other screens keep it. A quest of a Ritual, an errand, and an archived quest show neither Archive nor Mark as done, as before for Archive. The quest panel no longer has the Mark as done and Archive buttons under Does; an archived quest's panel keeps its Reopen button. The phone's header and a narrow window are unchanged.
Reason: The owner asked for these buttons at the top right, with the middle toggle of the sidebar removed.
References: CHG-0304, CHG-0308 (Done stays), [mission tracking](../capabilities/mission-tracking/specifications.md#ending-a-mission).
Validation: Biome clean, `bun run typecheck` passes on all workspaces, `vitest run apps/app` passes (78 files, 556 tests, 6 skipped) with a new test of the quest icon's state. Not checked: the look in a window, light and other themes, a phone. Unverified choices: the icon's filled state shows the quest tab only, and a quest's journal, lore and budget screens have no icon (the edge handle is gone there too).

## CHG-0528 · 2026-11-19 · The phone shows a realm's name again in the sidebar

Type: Code
Event: Delivery
Scope: `apps/app` (`shell/railStyles.ts`, `shell/railQuests.tsx`, `test/shell/railStyles.test.ts`)

Summary: On a phone, a realm's row in the sidebar showed its folder mark and no name. The name was styled on the quest rows' text style, which carries `flex: 1`, with `flexBasis: "auto"` and `flexGrow: 0` laid over it. Yoga, the phone's layout engine, reads `"auto"` as unset, so the name kept `flex`'s basis of 0 and got no width; the web build follows CSS and was never affected. The realm's name now has its own style, with only `flexShrink: 1`, so it takes the width of its text and shrinks when the row is short.
Reason: The owner reported it with a screenshot of the phone's sidebar.
References: CHG-0161 (the row), CHG-0497 (touch rows).
Validation: `vitest run apps/app` passes (77 files, 554 tests, 6 skipped, before CHG-0527's test) and the new guard reads the style's source (it cannot load react-native); Biome clean; `tsc --noEmit` in `apps/app` clean after the guard moved to `import.meta.glob`. Not checked: a phone. The cause is read from Yoga's rule, not seen in a build; no APK was made from this change.

## CHG-0529 · 2026-11-19 · Code simplification across the codebase: shared helpers, smaller files, no single-letter names

Type: Code
Event: Agreement and Delivery
Scope: `packages/contracts`, `packages/service`, `packages/controller`, `packages/relay` (tests), `apps/app`, `apps/desktop`

Summary: A behavior-preserving pass against the conventions, from a review of the whole codebase.
- Shared helpers: the update settings (`AppUpdateSettings`, `appUpdateSettingsOf`) were parsed twice, in the phone's `androidUpdates/settings.ts` and the desktop's `updates/store.ts`; both now read them through one `packages/contracts/src/appUpdateSettings.ts`. `isRecord` lives in `packages/contracts/src/objects.ts` and replaces four local copies (`releaseChoice.ts`, `pairedHosts.ts`, `serviceUpdates.ts`, `ownRelay.ts`). `ownRelay.ts` reads Cloudflare's error list through one `firstErrorOf`. The phone's updater reuses `messageOf`. `contextOf` is one function in `harness/tokenUsage.ts` for Claude Code and OpenCode.
- Branching and repetition: the three `switch` statements in `hostUpdate.ts` and `serviceUpdates.ts` are `if` chains (the app's lint rule rejects capitalized handler keys, so `Match.valueTags` does not fit there); `railStorage.ts` reads and keeps through two helpers instead of eight try blocks; `questTree.ts` sorts quests through one `latestFirstOf`.
- Files past 512 lines, split by responsibility with no change to their exports: `requests.ts` (761 to 469 lines, with `accountRequests`, `attachmentRequests`, `budgetRequests`, `journalRequests`, `loreRequests`, `pickerRequests` and `results`), `store.ts` (the migrations moved to `earlyStoreMigrations`, `midStoreMigrations`, `lateStoreMigrations`, beside the existing `recentStoreMigrations`), `opencode.ts` (548 to 442 lines, with `openCodePlanLimits` and `openCodeUsage`), `rituals.tsx` (767 lines to `ritualForm`, `ritualCard`, `scheduleRow`, `ritualStyles` and a 144-line `rituals.tsx`); and three test files, `workspaces.test.ts`, `rituals.test.ts` and `roomCore.test.ts`, now with fixtures `test/fixtures/workspaces.ts` and `test/fixtures/rituals.ts`.
- Names: every single-letter variable and parameter in production code and in tests became a word (`first`, `second`, `current`, `thread`, `index`, `candidate`), renamed through the compiler's symbol table; `x` and `y` for coordinates stay.
Reason: The owner asked for a review of the whole codebase with the code-simplifier skill, then for the refactors it found.
References: [conventions](../conventions.md) (Size, Branching, Naming).
Validation: Biome clean on 968 files; `bun run typecheck` passes on all workspaces; `TMPDIR=<repo>/.tmp-test CI=1 bun run test` gives 2160 passed, 55 skipped, 28 failed (2243 tests in 282 files; 2240 before this change plus 3 new tests of `appUpdateSettingsOf`). The 28 failures are the same 28 tests that fail on a clean checkout in a thread's sandbox: `git init` cannot copy its hook samples there (`claudeWorktrees`, `worktrees`, `approvalsFolders`, `folderPicker`, `ownCopies`, and one `.gitignore` test, now in `workspaceEntries.test.ts`). Not checked: those 28 on the owner's machine, the phone and desktop windows. Left as they were: 40 production files between 257 and 512 lines (the soft limit), `isRecord` in `packages/channel` (it cannot import `contracts`) and in the verification scripts, the per-harness `usageOf` (they read different field names).
