## CHG-0528 · 2026-11-19 · The phone shows a realm's name again in the sidebar

Type: Code
Event: Delivery
Scope: `apps/app` (`shell/railStyles.ts`, `shell/railQuests.tsx`, `test/shell/railStyles.test.ts`)

Summary: On a phone, a realm's row in the sidebar showed its folder mark and no name. The name was styled on the quest rows' text style, which carries `flex: 1`, with `flexBasis: "auto"` and `flexGrow: 0` laid over it. Yoga, the phone's layout engine, reads `"auto"` as unset, so the name kept `flex`'s basis of 0 and got no width; the web build follows CSS and was never affected. The realm's name now has its own style, with only `flexShrink: 1`, so it takes the width of its text and shrinks when the row is short.
Reason: The owner reported it with a screenshot of the phone's sidebar.
References: CHG-0161 (the row), CHG-0497 (touch rows).
Validation: `vitest run apps/app` passes (77 files, 554 tests, 6 skipped, before CHG-0527's test) and the new guard reads the style's source (it cannot load react-native); Biome clean; `tsc --noEmit` in `apps/app` clean after the guard moved to `import.meta.glob`. Not checked: a phone. The cause is read from Yoga's rule, not seen in a build; no APK was made from this change.

## CHG-0529 · 2026-11-19 · Code simplification across the codebase: shared helpers, smaller files, no single-letter names

Type: Code
Event: Agreement and Delivery
Scope: `packages/contracts`, `packages/service`, `packages/controller`, `packages/relay` (tests), `apps/app`, `apps/desktop`

Summary: A behavior-preserving pass against the conventions, from a review of the whole codebase.
- Shared helpers: the update settings (`AppUpdateSettings`, `appUpdateSettingsOf`) were parsed twice, in the phone's `androidUpdates/settings.ts` and the desktop's `updates/store.ts`; both now read them through one `packages/contracts/src/appUpdateSettings.ts`. `isRecord` lives in `packages/contracts/src/objects.ts` and replaces four local copies (`releaseChoice.ts`, `pairedHosts.ts`, `serviceUpdates.ts`, `ownRelay.ts`). `ownRelay.ts` reads Cloudflare's error list through one `firstErrorOf`. - Files past 512 lines, split by responsibility with no change to their exports: `requests.ts` (761 to 469 lines, with `accountRequests`, `attachmentRequests`, `budgetRequests`, `journalRequests`, `loreRequests`, `pickerRequests` and `results`), `store.ts` (the migrations moved to `earlyStoreMigrations`, `midStoreMigrations`, `lateStoreMigrations`, beside the existing `recentStoreMigrations`), `opencode.ts` (548 to 442 lines, with `openCodePlanLimits` and `openCodeUsage`), `rituals.tsx` (767 lines to `ritualForm`, `ritualCard`, `scheduleRow`, `ritualStyles` and a 144-line `rituals.tsx`); and three test files, `workspaces.test.ts`, `rituals.test.ts` and `roomCore.test.ts`, now with fixtures `test/fixtures/workspaces.ts` and `test/fixtures/rituals.ts`.
- Names: every single-letter variable and parameter in production code and in tests became a word (`first`, `second`, `current`, `thread`, `index`, `candidate`), renamed through the compiler's symbol table; `x` and `y` for coordinates stay.
Reason: The owner asked for a review of the whole codebase with the code-simplifier skill, then for the refactors it found.
References: [conventions](../conventions.md) (Size, Branching, Naming).

## CHG-0530 · 2026-11-19 · The Vault's folder is hidden from the three harness sandboxes, and each adapter probes that it is

Type: Code
Event: Delivery
Scope: `packages/service` (`core/vaultFolder.ts`, `core/execution.ts`, `harness/claudeArgs.ts`, `harness/codex.ts`, `harness/codexVaultProfile.ts`, `harness/openCodeSandbox.ts`, `harness/vaultDenial.ts`, `harness/vaultDenials.ts`, `main.ts`), `documentation/verification/2026-11-19-vault-read-denial/`

Summary: Connectors blueprint, Order step 1, with a disposable marker and no secret. Claude Code's sandbox settings deny reading the Vault's folder (`sandbox.filesystem.denyRead`, part of the restart key); Codex threads start on a named permission profile that extends `:workspace`, denies the folder and opens the network as before, in place of `workspace-write` (which it cannot be combined with); OpenCode's Seatbelt profile ends with a `file-read*` deny of the folder, and its bubblewrap command covers it with an empty folder. Each adapter reports a `VaultDenial` (Verified, Unverified, NotInstalled, AsksFirst) from a probe that reads a marker from inside its sandbox, beside an outside control and a control read inside, and fails closed. Claude Code's is always Unverified at start: no command runs its sandbox without a live model turn. Findings, run on macOS: the denial works in OpenCode's and Codex's sandboxes; **the macOS Keychain is readable from inside all three sandboxes**, Claude Code's included, so it is no second layer (ADR 0022 amended).
Reason: The owner authorized the build of connectors; the blueprint puts the probes first because the whole design rests on the sandbox claims.
References: [ADR 0022](../architecture-decision-record/0022-the-vault-encrypts-secrets-and-hides-its-folder-from-sandboxes.md), [connectors blueprint](../capabilities/connectors/blueprint.md), [verification](../verification/2026-11-19-vault-read-denial.md), CHG-0328.
Validation: see the verification note. The real Seatbelt, `codex sandbox` and Keychain tests passed outside the thread's sandbox and skip inside it. Not checked: Claude Code's denial and a Codex or OpenCode turn live, Linux, Windows; the owner runs `OUTLORE_LIVE_CLAUDE_PROBE=1 bun run test packages/service/test/vault/readDenialLive`.

## CHG-0531 · 2026-11-19 · The Vault: encrypted connector secrets with key custody, states and one writer

Type: Code
Event: Delivery
Scope: `packages/service` (`vault/`, `service.ts`, `work/promptPolicy.ts`), `documentation/architecture-decision-record/0022-*`, `documentation/capabilities/connectors/`

Summary: Connectors blueprint, Order step 2. `vault/` holds secrets in a records file sealed with AES-256-GCM (identifier and connector bound in), beside a header that names the key holder chosen once when the Vault is made. Key holders: the macOS Keychain (`security -i`, key on standard input), Windows DPAPI, the Secret Service (`secret-tool`) and a key file, behind one `KeyCustody` interface. States: Absent, Ready, Locked (holder unreachable), Lost (key gone, or its identifier differs), Corrupt; none but Ready writes, a Lost Vault may be emptied by the owner, and no key is made or holder changed silently. Writers run one at a time; a key move to another holder is explicit and keeps the old key until the header's rename commits. `Vault` offers `state`, `list`, `put`, `replace`, `remove`, `removeAllOf`, `moveKey`, `protection` and `withSecret`, the only read, which hands the callback a `Redacted` value. A secret is stored only while the folder's denial is verified for every installed harness, which the probes of CHG-0530 showed must hold for every key holder, not for the key file alone. The service makes the folder (mode 0700) at start, and its prompt policy refuses Claude Code's own Read, Grep and Glob of a path in it. No owner request, no connector and no screen use it yet; nothing real is stored.
Reason: The owner authorized the build of connectors; secrets need a place before a connector can have one.
References: [ADR 0022](../architecture-decision-record/0022-the-vault-encrypts-secrets-and-hides-its-folder-from-sandboxes.md) (amended), [connectors blueprint](../capabilities/connectors/blueprint.md), [verification](../verification/2026-11-19-vault-read-denial.md), CHG-0327, CHG-0328.
Validation: Biome clean; `bun run typecheck` passes on all workspaces; `CI=1 bun run test` gives 2,253 passed, 65 skipped, 0 failed in a thread's sandbox, and the Vault's folder of tests 73 passed outside it. Includes the secrecy property test (a random secret, raw and encoded, found in no file, answer or error through a turn and after removal) and key moves interrupted at each step. Not checked: Windows and Linux holders on a real host (stand-in runner only); a locked Keychain; an echoing connector backend (the gateway is built apart); the first Mac run of the whole path with a real secret. Open for the owner: whether the stricter rule (above) stands, and how Claude Code's denial gets verified, since `put` is refused on a host with Claude Code until it is.
