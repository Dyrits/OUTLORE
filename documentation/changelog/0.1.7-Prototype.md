## CHG-0440 · 2026-11-17 · A running quest stays in the sidebar beyond the three-quest limit

Type: Code
Event: Agreement and Delivery
Scope: Mission tracking, app shell

Summary: The owner asked that a running quest always appear in the sidebar, even beyond the three shown in a realm or the Borderlands. The sidebar now keeps the open quest and every quest in the Running state visible past that limit, each in its place in the newest-first list. The "Show all N quests" link is unchanged.
Reason: A quest that is working was hidden behind three newer quests and could only be found through the full list.
References: [mission tracking](../capabilities/mission-tracking/specifications.md) (Realm and Borderlands lists), `apps/app/src/shell/railOutline.ts` (`visibleQuestsOf`), `apps/app/test/shell/railOutline.test.ts`.
Validation: the new test "keeps every running quest past the normal placement limit, in its place in the list" failed before the change and passes after it; the other railOutline tests pass. Biome passes on both files. Not checked: the running app's sidebar, a realm list, or the full suite. In this checkout `pairingOffer.test.ts` and `qrScan.test.ts` fail to load (`Cannot find package '@outlore/channel/base64url'`), which this change does not touch.

## CHG-0441 · 2026-11-17 · Code Mode's core: connector calls from code, run in QuickJS inside the host

Type: Code
Event: Agreement and Delivery
Scope: Connectors, service, contract (settings)

Summary: The owner asked to implement Code Mode (Cloudflare's design) and chose, on 2026-11-17, to build its core now, ahead of the connectors it serves, and to run the code in QuickJS compiled to WebAssembly in the host. Built: `packages/service/src/connectors/` with `ConnectorGateway` (the gateway interface of the connectors blueprint, `listingFor` and `call`, and `noConnectorsLayer`, which offers no connector until the gateway is built), the executor (`codeExecutor.ts`, `codeRunner.ts`, `codeRun.ts`: a fresh QuickJS runtime per run, only the ECMAScript built-ins, `console`, and `connectors.<connector>.<tool>(input)`; 5 s of running time with waits not counted, 64 MB, 1 MB of stack, 200 calls, 8,000 logged characters), the declarations a thread reads (`codeTypes.ts`, from each tool's JSON Schema) and the tool (`codeMode.ts`, `run_connector_code`, an answer cut at 24,000 characters). The owner's settings gain `shouldUseCodeMode`, off by default; with it on, a thread's listing holds `run_connector_code` instead of its connector tools, a direct connector call is refused, and every call the code makes goes through `ConnectorGateway.call`, as a listed tool's would. Claude Code runs the tool unasked (`--allowedTools`); the gateway asks per write. New dependencies (MIT, pinned): `quickjs-emscripten-core` 0.32.0 and `@jitl/quickjs-singlefile-mjs-release-sync` 0.32.0, the one job neither Effect nor the platform covers (a sandboxed interpreter).
Reason: Code Mode was agreed (CHG-0324) as a toggle over connector tools; the owner wanted it started now. With no gateway, no thread is offered it yet: it switches on for real when the connectors' gateway replaces `noConnectorsLayer`.
References: [ADR 0023](../architecture-decision-record/0023-code-mode-runs-in-quickjs-inside-the-host.md), [connectors specification](../capabilities/connectors/specifications.md#code-mode) and [blueprint](../capabilities/connectors/blueprint.md) (Order 6), [backlog](../backlog.md), `packages/service/src/connectors/`, `packages/service/src/work/mcp.ts`, `packages/service/src/work/threads.ts`. `@cloudflare/codemode` 0.5.6 was read for its design and is not a dependency.
Validation: 25 new tests: `codeExecutor.test.ts` (12, written before the executor; its first run failed four on a use-after-free when a call ended inside `runFork`, fixed by settling after QuickJS leaves the call), `codeTypes.test.ts` (4) and `codeMode.test.ts` (9, written after their code and not seen red; through the real tool server with a fake gateway: same result and same gateway call as a direct call, a write held until the owner answers while the code waits, denied and switched-off calls thrown into the code, nothing but `connectors` reachable, direct calls refused while on and the tool unknown while off). The settings tests now expect the new field, including a saved settings row without it reading `false`. Biome, the typecheck of seven workspaces and the full suite pass; the service bundles (`bun build`, as the desktop build does) with QuickJS inside.
Evidence: [Verification](../verification/2026-11-17-code-mode-core.md). Not checked: a real connector, a live harness run, the gain in tokens, the Charter's switch (not built), whether a change of the setting reaches a reused harness process before its next start.
