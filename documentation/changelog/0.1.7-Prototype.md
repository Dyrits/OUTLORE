# Changelog: 0.1.7-Prototype

## CHG-0298 · 2026-11-15 · An Android APK of the same app on every release tag

Type: Code
Event: Agreement and Delivery
Scope: Release workflow, App, Device pairing

Summary: The owner asked that the release's build also produce an APK, so there is a mobile app and not only the browser one, the same app since it is Expo and React Native. Agreed (the owner took the recommendations): the pipeline and the code so the app runs on Android; `expo prebuild` and Gradle on GitHub Actions, no EAS; a release keystore held in repository secrets; the APK attached to the GitHub release as `Outlore-<version>-android.apk` and listed in `SHA512SUMS.txt`. Built: an `android` job in `package.yml` (the release now waits for it and expects five files); `app.config.ts` (version from the tag, `versionCode` from the run number), `android.package` `app.outlore.mobile`, and `plugins/withReleaseSigning.js` (the release build signs with the keystore named by environment variables, the debug key without them); `expo-crypto` supplies `crypto` that Hermes lacks (`cryptoPolyfill.native.ts`); pairings live in `expo-secure-store` (`pairingStorage.native.ts`); the app is remote-only like a browser and says "This phone"; `PageSettings.deviceKind` lets the host list it as a phone.
Reason: The browser app exists and the code was meant to build natively (0009); nothing built or distributed a native app.
References: [0009](../architecture-decision-record/0009-one-expo-app-everywhere.md), [device-pairing specification](../capabilities/device-pairing/specifications.md), [verification](../verification/2026-11-15-android-apk.md), `.github/workflows/package.yml`, `apps/app/app.config.ts`.
Validation: Biome, the workspace typecheck, the full suite (1,607 passed, 54 skipped inside the sandbox), `expo export --platform android` (a 6.3 MB Hermes bundle) and `--platform web`, and `expo prebuild --platform android` (the signing plugin's output read). New tests: the secure-store storage reads a removed key as absent at once; a phone pairs and the host lists it as a phone while a browser stays a desktop. Not checked: Gradle (no JDK here), an APK, a phone or emulator, the workflow itself, and the release key (the owner makes it; a tag without it fails).

## CHG-0441 · 2026-11-17 · Code Mode's core: connector calls from code, run in QuickJS inside the host

Type: Code
Event: Agreement and Delivery
Scope: Connectors, service, contract (settings)

Summary: The owner asked to implement Code Mode (Cloudflare's design) and chose, on 2026-11-17, to build its core now, ahead of the connectors it serves, and to run the code in QuickJS compiled to WebAssembly in the host. Built: `packages/service/src/connectors/` with `ConnectorGateway` (the gateway interface of the connectors blueprint, `listingFor` and `call`, and `noConnectorsLayer`, which offers no connector until the gateway is built), the executor (`codeExecutor.ts`, `codeRunner.ts`, `codeRun.ts`: a fresh QuickJS runtime per run, only the ECMAScript built-ins, `console`, and `connectors.<connector>.<tool>(input)`; 5 s of running time with waits not counted, 64 MB, 1 MB of stack, 200 calls, 8,000 logged characters), the declarations a thread reads (`codeTypes.ts`, from each tool's JSON Schema) and the tool (`codeMode.ts`, `run_connector_code`, an answer cut at 24,000 characters). The owner's settings gain `shouldUseCodeMode`, off by default; with it on, a thread's listing holds `run_connector_code` instead of its connector tools, a direct connector call is refused, and every call the code makes goes through `ConnectorGateway.call`, as a listed tool's would. Claude Code runs the tool unasked (`--allowedTools`); the gateway asks per write. New dependencies (MIT, pinned): `quickjs-emscripten-core` 0.32.0 and `@jitl/quickjs-singlefile-mjs-release-sync` 0.32.0, the one job neither Effect nor the platform covers (a sandboxed interpreter).
Reason: Code Mode was agreed (CHG-0324) as a toggle over connector tools; the owner wanted it started now. With no gateway, no thread is offered it yet: it switches on for real when the connectors' gateway replaces `noConnectorsLayer`.
References: [ADR 0023](../architecture-decision-record/0023-code-mode-runs-in-quickjs-inside-the-host.md), [connectors specification](../capabilities/connectors/specifications.md#code-mode) and [blueprint](../capabilities/connectors/blueprint.md) (Order 6), [backlog](../backlog.md), `packages/service/src/connectors/`, `packages/service/src/work/mcp.ts`, `packages/service/src/work/threads.ts`. `@cloudflare/codemode` 0.5.6 was read for its design and is not a dependency.
Validation: 25 new tests: `codeExecutor.test.ts` (12, written before the executor; its first run failed four on a use-after-free when a call ended inside `runFork`, fixed by settling after QuickJS leaves the call), `codeTypes.test.ts` (4) and `codeMode.test.ts` (9, written after their code and not seen red; through the real tool server with a fake gateway: same result and same gateway call as a direct call, a write held until the owner answers while the code waits, denied and switched-off calls thrown into the code, nothing but `connectors` reachable, direct calls refused while on and the tool unknown while off). The settings tests now expect the new field, including a saved settings row without it reading `false`. Biome, the typecheck of seven workspaces and the full suite pass; the service bundles (`bun build`, as the desktop build does) with QuickJS inside.
Evidence: [Verification](../verification/2026-11-17-code-mode-core.md). Not checked: a real connector, a live harness run, the gain in tokens, the Charter's switch (not built), whether a change of the setting reaches a reused harness process before its next start.

## CHG-0442 · 2026-11-17 · A conversation opens on its last messages

Type: Code

## CHG-0443 · 2026-11-17 · The Android build merged with main, so a phone pairs from the release

Type: Code
Event: Delivery
Scope: App, Device pairing, Release workflow

Summary: The owner expected the APK in 0.1.6-Prototype; `worktree/android-apk` (CHG-0298) had never been merged, so it was missing and the phone app could not pair. Main was merged into the branch. Since main had moved the link to Effect with a `ControllerKind` per controller, the phone became a third kind (`"phone"`, "This app", named "phone") and the page's `deviceKind` setting became `PageSettings.kind`, left out by a browser. The app keeps main's `useHostConnection` (its `deviceNoun`, pairing links, scanner) and takes the branch's native storage (`pairingStorage()`) and `isNativeApp`; `remoteDeviceNoun` is gone. `app.json` holds both plugin sets (font, secure store, release signing, camera) and the `outlore` scheme. The release workflow keeps main's checksums step with the APK added. `apps/app/app.config.ts` joins Biome's list of files allowed a default export, which Expo requires. A browser is still listed as a browser (main's CHG-0309), not a desktop as the branch's test said.
Reason: The APK goes out with the next release, and the phone app pairs only with the native storage and the `crypto` polyfill of the branch.
References: CHG-0298, CHG-0436, CHG-0437, `packages/controller/src/linkFailure.ts`, `packages/controller/src/browserLink.ts`, `apps/app/src/foundation/browser/page.ts`.
Validation: Biome, the seven typechecks, and the full suite inside the sandbox (248 files passed, 4 skipped; 2,012 tests passed, 54 skipped). A test pairs a phone and a browser and reads them back as phone and browser. First local Gradle build (`expo prebuild`, then `assembleRelease` for arm64-v8a with Temurin 17, Build Tools 37.0.0 and platform 37.0, debug-signed): a 34 MB APK, installed with `adb` on the owner's Android phone, where it starts (`ReactNativeJS: Running "main"`, no crash and no script error in the log). Not checked: the screens (the phone was locked), a pairing from the phone, the camera, an `outlore://` link, the workflow's `android` job, and a release-signed build (the repository has no `ANDROID_*` secrets yet, so a tag fails).
