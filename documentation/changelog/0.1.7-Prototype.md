## CHG-0441 · 2026-11-17 · Own copy: a side-quest works and commits in a git worktree Outlore makes, without asking

Type: Code
Event: Agreement and Delivery
Scope: Workspace attachment, thread tree, action approval, service

Summary: Threads kept asking the owner for anything done with a git worktree ("Create the code-mode worktree. This runs outside the sandbox"). Cause: Claude Code (2.1.326) blocks writes to `<folder the thread starts in>/.git/worktrees` inside its sandbox (a built-in rule, beside `.git/hooks` and `.git/config`, that Outlore's `allowWrite` cannot lift), so `git worktree add` and `remove`, and every `git add`, `commit` or `checkout` in an existing worktree from the checkout (they lock `.git/worktrees/<name>/index`), failed in the sandbox and asked. Edits and other commands in a worktree already ran unasked (CHG-0273). A live probe (Claude Code in `-p` with the sandbox on, started inside a linked worktree) showed that a thread whose folder *is* the worktree may write that worktree's own records, `.git/objects`, `refs` and `logs`, while `.git/hooks` and new `.git/worktrees` entries stay blocked. So the service now makes the worktree, and the thread starts inside it: `open_thread` takes `ownCopy: true`; the service (outside any sandbox) checks that the workspace is the top folder of a git repository, adds `/.worktrees/` to the repository's `.git/info/exclude` when it is not ignored already, and runs `git worktree add -b mission/<name> <workspace>/.worktrees/<name> <commit>`, from the commit the opener works on (the workspace, or the opener's own copy). `<name>` is the quest title's words and the thread's short id. The new thread's folder is that worktree; threads it opens share it unless they ask for their own. Its starting context names the copy, its branch and the workspace, tells it to commit there and name the branch in its result, and says the copy has no installed packages. Migration 0056 adds `threads.own_copy` and `own_copy_branch` (0054 is taken by `worktree/context-window`). A thread whose own copy folder is gone is held as a missing workspace. The thread instructions now steer branch work to `ownCopy` and say a self-made worktree, and each commit in it from the checkout, asks. The owner chose: build Own copy now, worktrees in `<workspace>/.worktrees/` (same disk, APFS clones) instead of the spec's `~/.iskios/worktrees/`, and no merge button or archive cleanup in this change; the opener merges with plain git, which runs unasked from the checkout.
Reason: The owner: "I always have this request for permission, for absolutely anything. Can we make worktree being part of the sandbox?"
References: [workspace attachment](../capabilities/workspace-attachment/specifications.md#own-copy), [action approval](../capabilities/action-approval/specifications.md), CHG-0273, `packages/service/src/work/ownCopies.ts`, `tree.ts`, `workspaces.ts`, `startingContext.ts`, `turnAdmission.ts`, `threadTools.ts`, `threadToolHandlers.ts`, `packages/service/src/harness/instructions.ts`, `packages/service/src/core/recentStoreMigrations.ts`.
Evidence: [Verification](../verification/2026-11-17-own-copy.md).
Validation: the block was reproduced in this thread's sandbox (`touch .git/worktrees/<name>/index.lock`: Operation not permitted) and located in Claude Code 2.1.326's own sandbox rules; the probe above ran once with the owner's approval. Six new tests in `test/work/ownCopies.test.ts` (naming; a worktree in `.worktrees` on a `mission/` branch with the thread started there and the repository status clean; a thread beneath sharing the copy and the opener staying in the workspace; refusals with no workspace and for a subfolder of a repository), written with the code, not seen red. Biome, the workspace typecheck and the full suite inside Claude Code's sandbox pass (2,014 passed, 54 skipped). Not checked: a live Claude Code side-quest opened with `ownCopy` committing unasked through Outlore (the probe used a plain `claude -p`); Codex and OpenCode in an own copy (their sandboxes write the folder only, so their commits probably still ask); the owner's own Own copy choice when opening a side-quest, the merge button and archive cleanup (not built).
