## CHG-0738 · 2026-11-25 · Copy buttons on replies and code blocks

Type: Code
Event: Agreement
Scope: Conversation panes

Summary: An agent's reply now has a Copy button at the right of the line under it, which copies the reply's Markdown text, and every code block in a reply has a Copy button in its top right corner, which copies only that block's code.

Reason: The owner asked for a way to copy a response, and a code block, directly, for example to paste release notes (2026-11-25).

## CHG-0746 · 2026-11-25 · Reply opens the child thread, not a box at the bottom

Type: Code
Event: Agreement
Scope: Conversation panes, Reply, quest and errand anchors

Summary: A Reply on a message opens its child at once: an empty quest from a Chronicler message, an empty errand from a message of a quest, in every layout, hung from the message, with its own composer taking the first message.
`ReplyToMessage.text` is optional; absent, the child is started empty, and an empty errand is not woken.
The bottom Reply box and the starter pane's reply banner are gone.
The owner asked, in the same discussion, that the first message of a quest or errand opened without a Reply be copied to its parent conversation as conversation only, so that it becomes the anchor and wakes only the child.
This reverses CHG-0572 for empty quests, and extends it to errands opened from the errand pane.
The pinned root and the reply count treat a copy that repeats an errand's first message as the errand's own root, as they do for a quest.
The agreed rest: an empty child the owner never writes in is kept and can be deleted; no system message is posted for an open.
The thread instructions say that a reply stands in one place, as in Slack: the child answers its first message in the child and never in the parent; a parent woken by the owner's words echoed with Also send to answers only when they are for it, in its own conversation, and Chronicler ends its turn without a reply once a quest takes the owner's words.
A child cannot tell that a later message was also sent to its parent, so that choice rests on the instruction alone.
References: [conversation panes](../capabilities/conversation-panes/specifications.md#errands-as-replies).
Validation: Biome, the app and service typechecks, the 870 app tests, the 790 service work tests and the instruction tests pass (new tests in `replies.test.ts` and `questOrigins.test.ts`; `questMoves.test.ts` expects the copy); the desktop window check and owner acceptance are pending.

## CHG-0748 · 2026-11-25 · A thread reads its opener's conversation on demand

Type: Code
Event: Agreement
Scope: Thread tree, Opening a thread, Starting context

Summary: A thread opened beneath another no longer starts with a snapshot of its opener's 40 latest messages, re-sent with every turn.
It starts with the journal, its lore, and one line saying how many messages its opener has.
The new thread tool `read_parent_messages` reads them when needed: the latest first, paged back with `before`, or searched with `query`.
The search is SQLite full-text search (FTS5, BM25 ranking, word endings and prefixes, any word matching, more words ranking higher), kept current by triggers (migration 0079 `message_search`), with no embeddings.
Where the SQLite build has no full-text search, the tool ranks the newest thousand messages by how many of the words each holds.
An aside cannot read its opener's conversation, and a quest's top thread has no opener.
Reason: The owner found 40 messages a lot and asked that a child go back into the history as it needs, with a search (2026-11-25).
References: [thread tree](../capabilities/thread-tree/specifications.md#opening-a-thread); CHG-0043 for the earlier cap.
Validation: Vitest `journal.test.ts` (the line, paging, search with stemming and ranking, the fallback without the index) and `startingContext.test.ts`; full service suite and typecheck run, desktop check pending.

## CHG-0749 · 2026-11-25 · A thread the owner opens reads its opener's last five messages on its first turn

Type: Code
Event: Agreement
Scope: Thread tree, Opening a thread, Starting context

Summary: Besides the line on its opener's conversation and `read_parent_messages` (CHG-0748), an errand the owner opens with a message of its own receives its opener's last 5 messages, each clipped to 500 characters, on its first turn only.
Later turns carry the line alone, so the tail is not re-sent as new input with every turn.
An errand an agent opens, an errand a Reply opens, and an aside get no tail.
The tail is captured when the errand is opened (migration 0080 `thread_opener_tail`, `threads.opener_tail`), and the size preview counts it.
Reason: A short request such as "fix this" leans on the latest messages, and a thread cannot tell what it is missing; the owner chose to try it with the tools behind it (2026-11-25).
References: CHG-0748; [thread tree](../capabilities/thread-tree/specifications.md#opening-a-thread).
Validation: Vitest `journal.test.ts`, `replies.test.ts`, `startingContext.test.ts` (59 tests), each claim shown able to fail by mutation; the proof is [2026-11-25-opener-tail-and-parent-search](../verification/2026-11-25-opener-tail-and-parent-search.md); desktop check pending.
