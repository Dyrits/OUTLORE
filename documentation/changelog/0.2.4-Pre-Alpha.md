# Changelog: 0.2.4-Pre-Alpha

## CHG-0677 · 2026-11-24 · Typing in a conversation terminal no longer reports a service failure

Type: Code
Event: Delivery
Scope: Conversation terminal, host service

Summary: The service answered typing, resizing, and closing a conversation shell with no value. The wire contract allows only `null` for those requests, so encoding each answer failed after the shell had already received the keys. The terminal kept working, but every keystroke and resize showed "The service failed unexpectedly." in the panel. These requests now answer `null`. The fault had been present since the shells moved into the host service (CHG-0644). The service's own tests called the handlers directly and never encoded their answers.
Reason: The owner reported that the terminal still showed "The service failed unexpectedly." after `git pull` in the 0.2.3-Pre-Alpha app (2026-11-24).
Validation: A new test in `packages/service/test/work/terminals.test.ts` sends each request as a wire frame through the real service and requires a Success frame. Before the fix, resize and close returned the owner's exact Failure frame; afterward, all 14 terminal tests passed when run outside the sandbox with a real pseudo-terminal, including typing into an open shell, and the frame tests passed. The running desktop app was not checked; the fix reaches it in the next build.
