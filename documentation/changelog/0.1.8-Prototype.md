# Changelog: 0.1.8-Prototype

## CHG-0445 · 2026-11-18 · The Android app no longer crashes once a pairing connects

Type: Code
Event: Delivery
Scope: App (Guild Hall hub), release

Summary: The owner reported that the Android app (0.1.7-Prototype, installed from the debug-signed build) crashed after a pairing was attempted. `adb logcat -b crash` held two crashes, both `TypeError: undefined is not a function` thrown in `hubOf` and called from `GuildHallHub`, which renders as soon as a pairing connects. Cause: `hubOf` sorted the quests with `Array.prototype.toSorted`, and Hermes, the phone app's engine (React Native 0.88.1), does not have it. The engine's own Array table in `libhermesvm.so` of the installed APK lists `toReversed`, `toSpliced`, `with`, `findLast` and `flatMap`, but not `toSorted`. TypeScript's library does know it, so the typecheck passed. `hubOf` now sorts a copy (`[...missions].sort(...)`). A guard test fails when the code the phone bundles (the app, `contracts`, `controller`) calls `.toSorted(`. This hotfix release carries that fix and nothing else; the version moves to 0.1.8-Prototype.
Reason: A phone that pairs but crashes on the first screen is unusable, and 0.1.7-Prototype is the first release with the Android app.
References: CHG-0298, CHG-0443, `apps/app/src/conversation/guildHall.ts` (`hubOf`), `apps/app/test/conversation/guildHall.test.ts`, `apps/app/test/foundation/hermesBuiltins.test.ts`, `apps/app/test/raw.d.ts`.
Validation: the new test in `guildHall.test.ts` ran `hubOf` without `Array.prototype.toSorted`: it failed with the crash's `TypeError` before the fix and passes after. The guard test failed on a planted `.toSorted(` call and passes on the tree. All 72 app test files (511 tests passed, 8 skipped), the app's typecheck and Biome pass. Not checked: the fixed app on the phone (needs the 0.1.8 APK), the rest of a pairing from the phone (camera, `outlore://` link), and other built-ins newer than Hermes: the client code was searched for `toSorted`, `toReversed`, `toSpliced`, `findLast`, `Object.groupBy`, `Array.fromAsync`, `Promise.withResolvers` and the new Set methods, and only `toSorted` is used (the few `.at(-1)` calls are on arrays, which Hermes has); a built-in outside that list was not looked up.

## CHG-0447 · 2026-11-18 · Agreement: voice input is transcribed on the owner's device with whisper.cpp

Type: Documentation
Event: Agreement
Scope: Voice input (new), architecture

Summary: The owner asked for voice instead of typed text in the message boxes. Settled in the quest's thread: no vendor receives audio; speech-to-text only, no direct voice for now; the `base` model (142 MiB), many languages; the phone transcribes on the phone itself. Owner's approach, tried first: whisper.cpp on both the desktop and the phone, one engine and one model file ([ADR 0024](../architecture-decision-record/0024-speech-is-transcribed-on-the-owners-device-with-whisper-cpp.md)). This batch is the first increment: the desktop's transcriber in the service, tested against a real engine. The composer's microphone button, the recording, the phone's native module and the start-and-stop choice are later batches. Open for the owner: the licence exclusions (proposal in the draft) and whether the phone spike should run first.
Reason: A voice input must not send the owner's speech to a vendor ([Local data](../requirements.md#privacy-and-data)), and one engine on both apps keeps one set of results and one model.
References: [voice-input draft](../capabilities/voice-input/draft.md), [research](../research/voice-input-2026-11-18.md), [ADR 0024](../architecture-decision-record/0024-speech-is-transcribed-on-the-owners-device-with-whisper-cpp.md).
Validation: none yet at agreement; the batch's checks are in CHG-0448.

## CHG-0448 · 2026-11-18 · The service transcribes a 16 kHz WAV recording with whisper.cpp

Type: Code
Event: Delivery
Scope: Service (voice, new `packages/service/src/voice/`)

Summary: `checkWav` reads a WAV header and refuses any recording that is not 16 kHz, mono, 16-bit uncompressed PCM, empty, or cut short, each with a plain reason. `transcribeWav` runs whisper.cpp's `whisper-cli` on that file with `-np -nt -l <language>` (`-ng` when the GPU is off), returns the trimmed transcript, and fails with a plain reason if the engine is missing, exits with an error, or runs past five minutes. `readTranscriberSettings` reads `OUTLORE_WHISPER_CLI`, `OUTLORE_WHISPER_MODEL` (both required), `OUTLORE_WHISPER_LANGUAGE` (default `auto`) and `OUTLORE_WHISPER_GPU` (default on) through `Config`, so a missing setting is an ordinary failure. Nothing is bundled, downloaded or shown in the app yet; the owner's environment names the engine and the model for now.
Reason: The first increment of the agreed approach, small enough to check against the real engine before the desktop's microphone, the phone, and the bundling are built.
References: CHG-0447, [ADR 0024](../architecture-decision-record/0024-speech-is-transcribed-on-the-owners-device-with-whisper-cpp.md), `packages/service/src/voice/transcribe.ts`, `packages/service/test/voice/transcribe.test.ts`, whisper.cpp at commit `8302b819` (MIT), model `ggml-base.bin` (sha256 `60ed5bc3dd14eea856493d334349b405782ddcaf0028d4b5df4088345fba2efe`, from the Hugging Face repository `ggerganov/whisper.cpp`).
Validation: the tests run on the worktree with `ELECTRON_RUN_AS_NODE=1 npx electron node_modules/vitest/vitest.mjs run packages/service/test/voice/transcribe.test.ts`. Without the engine: 7 passed, 2 skipped (the engine's tests need its paths). With the engine built from the pinned commit and the `base` model, with the GPU off (the sandbox aborts Metal): 9 passed, including the transcript of whisper.cpp's sample `jfk.wav`. Biome and `tsc -p .` in `packages/service` pass. Measured on this Mac, inside the sandbox, the CPU run on the 11-second sample took 0.53 s; automatic language detection gave the same sentence. Not measured: peak memory (the sandbox hides the engine's process from `ps`), the GPU path outside the sandbox, latency on a phone, and Windows or Linux. Not checked: the full suite, the composer, the phone.
