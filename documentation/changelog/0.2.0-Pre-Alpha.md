## CHG-0595 · 2026-11-20 · Run what Claude Code does after a background command ends as a turn

Type: Code
Event: Agreement and Delivery
Scope: `packages/service` (Claude Code adapter, harness process pool, turn admission)

Summary: when a turn ended while a background command still ran, the command's end woke Claude Code, which then worked with no Outlore turn open. Its replies were not recorded until the owner's next message, and its commands, such as `git commit`, were refused with "This thread is not at work, so nothing runs."
The adapter now reads the process between turns; a `task_notification` makes the pool ask the thread runner for a turn with no message, so the replies and steps are recorded, a line in the thread gives Claude Code's own summary of the ended command, and prompts are answered as in any turn. A woken process the thread may not run (Stopped, held, over budget) is closed.
A process with background tasks pending (`background_tasks_changed`) is kept for an hour instead of the idle timeout, so the command is not killed before it ends.
Probe: Claude Code 2.1.328 in stream-json mode ended the turn with `result`, then sent `task_notification`, `init`, replies and a second `result` unprompted when the command ended 7 s later.
Validation: new pool tests (7) and stand-in Claude Code tests (2), which fail without the change; the harness and work suites pass. Not yet seen in the app with a real long-running command. [Verification](../verification/2026-11-20-background-wake-turns.md)

Event: Delivery
Scope: `packages/service` (Codex harness, the Vault's permission profile)

Summary: Every Codex turn failed once the Vault's folder was hidden from Codex's sandbox (ADR 0022). `thread/start` took the profile's definition (`permissions.outlore.*`) in its `config`, but a turn reloads Codex's settings without that thread's overrides, finds no profile named `outlore`, and fails with that message after five retries. Reproduced with a direct `codex app-server` session on Codex 0.170.0: the `outlore` profile fails, `workspace-write` and the built-in `:workspace` profile pass.
- The profile is now defined on the process: `codex app-server -c default_permissions="outlore" -c permissions.outlore.…`, and `thread/start` only names it. A profile in the process settings needs `default_permissions`, or Codex refuses to start.
- The same session with those arguments answers a turn. The deny rule itself is the one `readDenial.test.ts` already probes with `codex sandbox`.
Reason: The owner's screenshot of the failed turn. The 2026-11-19 verification had tried `thread/start` and `codex sandbox` but "no live Codex turn was run".
Validation: Direct app-server session (profile in `thread/start`: turn fails; profile in startup arguments: turn answers "ok"); `adapterDenial.test.ts` passes (10 tests); `bun run typecheck` passes. Not checked: the full suite, and a turn from the Outlore window.
