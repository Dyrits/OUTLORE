Type: Code
Event: Delivery
Scope: Workshop Companions

## CHG-0717 · 2026-11-25 · Paired-device links gain sequenced framing and direct-channel upgrade orchestration

Type: Code
Event: Delivery
Scope: Channel (`@outlore/channel`)

Summary: Added `PathLink`, `DirectControl` (`DirectOffer`, `DirectAnswer`, `DirectRefusal`), `directPeer`, `directSettings`, and `directUpgrade` to `@outlore/channel`. A paired device's link keeps the relay Noise NK session as fallback and, once both sides enable framing, sequences application frames (`DATA`/`ACK`/`CONTROL`/`LINK`), replays unacknowledged frames over the relay on drop or after 3 missed 10-second beats, and negotiates a direct WebRTC data channel through one offer and one answer inside the encrypted relay session. A fresh Noise NK handshake bound to `outlore-direct/1 <room> <attempt>` runs inside the data channel so DTLS is not the end-to-end layer.
Reason: Authorized by the owner on 2026-11-25 to move steady-state paired-device traffic off the shared Cloudflare relay after it hit the 100,000 Durable Object requests/day free-tier cap on 2026-11-24, while keeping the relay for pairing, signaling, and automatic fallback.
References: [Device pairing](../capabilities/device-pairing/specifications.md), [ADR 0026](../architecture-decision-record/0026-direct-webrtc-channels-with-werift-and-relay-fallback.md).
Validation: Workspace typecheck, Biome check, and full test suite passed (3,159 passed, 24 skipped, 0 failed), including `packages/channel/test/pathLink.test.ts` and `packages/channel/test/directUpgrade.test.ts` with Effect `TestClock`.

## CHG-0718 · 2026-11-25 · Paired desktop and web devices upgrade to direct WebRTC channels with relay fallback

Type: Code
Event: Delivery
Scope: Host service, controller, web app, Workshop Remote access

Summary: Wired direct WebRTC channels into the host service and desktop controller via `werift` (`^0.28.0`, MIT, pure TypeScript, lazy-loaded with `iceUseDefaultStunServer: false`) and into the web app via the browser's `RTCPeerConnection`. Default public STUN is `stun:stun.cloudflare.com:3478` (configurable via `OUTLORE_STUN_SERVERS`; disableable on the host via `OUTLORE_DIRECT=false`). Only same-release peers enable framing and attempt direct upgrades, leaving cross-release update links unframed on the relay. A host caps concurrent direct channels at 16 and reports `PairedDevice.isDirect` so the Workshop shows `connected now, direct`. The mobile app (Android/Hermes) has no built-in WebRTC and stays on the relay.
Reason: Completes the direct-path upgrade across host and clients (following CHG-0717) without adding native C++ modules to the Electron release or standalone host.
References: [Device pairing](../capabilities/device-pairing/specifications.md), [ADR 0026](../architecture-decision-record/0026-direct-webrtc-channels-with-werift-and-relay-fallback.md), [Architecture](../architecture.md).
Validation: Workspace typecheck, Biome check, and full test suite passed (3,159 passed, 24 skipped, 0 failed), including `packages/service/test/remote/directPath.test.ts` (real local relay, full host service, real `werift` peers on both sides) and `apps/app/test/settings/remoteAccess.test.ts`. Real-network NAT traversal from a phone or second network and native Android WebRTC were not exercised in the sandbox.
