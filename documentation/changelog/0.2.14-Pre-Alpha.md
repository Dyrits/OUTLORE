# 0.2.14-Pre-Alpha

## CHG-0796 · 2026-11-28 · The Companions tab is two balanced columns of cards with one chain editor, as in the prototype

Type: Code
Event: Delivery
Scope: `apps/app/src/editors/companionPicker.tsx`, `presetChooser.tsx`, `presetEditor.tsx`, `presetChainEditor.tsx`, `presetChainRows.tsx`, `presetChain.ts`, `presetEntries.ts`, `presetOverwrite.tsx`, `backupsEditor.tsx`, `apps/app/src/settings/companionStyles.ts`, `workshopCompanions.tsx`, the tests of `apps/app/test/editors`; `threadCompanionDetails.tsx` and `threadPresetEditor.tsx` removed
Summary: The list is one card for each preset (numbered models, provider icon, effort at the right) and a dashed **+ Add a companion**, with no "Presets" heading and no **Custom** entry; the list and the editor have equal widths (the fixed 176 column is gone) and a gap of 16. Choosing a card hands its stack to the thread and opens its chain at once in the editor: there is no Edit or Done step. Rows are named by their model (with account and effort), never "Companion" or "Backup N", with a **Primary** pill on row 1, a remove cross and a chevron on each, a **FALLBACK ORDER** header and a dashed **+ Add a model**. The footer has Discard, Save as new and a primary Overwrite "<name>", disabled while nothing changed. Overwrite and Save as new from a thread also put the saved chain on the thread. `PresetEntry` lost its single-valued `kind`.
Reason: The owner judged the previous layout "terrible" next to the prototype and asked for balanced columns, model names instead of "Backup 1, 2, 3", no Custom entry or Presets header, and the prototype's behavior. It replaces CHG-0789's Custom entry and edit mode.
References: [verification](../verification/2026-11-28-companion-menu-prototype.md), [companion-presets specifications](../capabilities/companion-presets/specifications.md), CHG-0789, CHG-0791 to CHG-0795.
Validation: Biome (94 files), `tsc --noEmit` for `apps/app` (exit 0) and `CI=1 bunx vitest run apps/app` (136 files, 1,153 passed, 6 skipped) pass.
Not run: a desktop window or phone (the look and the fluidity are the owner's to judge), a component test of the Overwrite and Save as new handover to the thread.
