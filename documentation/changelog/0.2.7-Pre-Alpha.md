# 0.2.7-Pre-Alpha

## CHG-0722 · 2026-11-25 · Antigravity reports its four plan limits, each under its own name

Type: Code
Event: Delivery
Scope: Antigravity harness, plan limits

Summary: The Antigravity adapter now reads its plan limits from the CLI's own `agy --print "/usage" --output-format json --print-timeout 10s` on the computer's own sign-in, and returns the four limits of its two model groups (a 5-hour and a weekly limit each for `Gemini Models` and `Claude and GPT models`).
A plan limit report gains an optional `label`, and the service shows it in place of the window-length name, so the four limits read "Gemini Models · 5-hour", "Gemini Models · Weekly", and so on instead of colliding as two "5-hour" and two "Weekly" windows.
A bucket nobody has used (reset time 1970-01-01T00:00:00Z) reads as unused with no reset time; a command that fails, prints no JSON, or answers a status other than SUCCESS fails the read, so the last reading stays and the usual wait applies; an added account reports none.
The command spends no tokens and reads no token file (ADR 0008, Comply with provider terms).
The display of plan usage is not changed: the owner likes the popup and dislikes the circles, and chooses among three alternatives in the [mockup](../art-direction/2026-11-25-plan-usage-display.html).
Reason: The owner asked on 2026-11-24 for Antigravity's plan limits, verified through its own usage command, and for the circles to be reconsidered.
References: [Plan limits](../capabilities/budget-control/specifications.md#plan-limits), [backlog](../backlog.md).
Validation: Five new checks in `antigravityPlanLimits.test.ts` (the four limits with labels and used shares, the exact command and environment, an added account, a failed or refused or unreadable answer, no groups and unreadable buckets) and one in `planLimits.test.ts` (a harness's label is kept) passed against the Antigravity stand-in; the real command was run once on this computer and its output shape is the test's. Typecheck of the app and the controller passed; the service typecheck reports only `werift` missing from the installed packages, as on the main checkout. The two `harnesses.test.ts` checks of an added account's folder fail with and without this change. Not yet seen: the live app showing the four limits (the current rings draw four rings for them until the display is chosen).
