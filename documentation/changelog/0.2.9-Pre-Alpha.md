## CHG-0753 · 2026-11-26 · Plan usage card in the order the popup's table uses

Type: Code
Event: Delivery
Scope: Plan usage rail, Antigravity plan limits

Summary: The card that opens when hovering a provider's logo in the rail now lists its limits grouped by model group, as the popup's table does, with the shorter window first inside each group.

References: [plan usage display alternatives](../art-direction/2026-11-25-plan-usage-display.html).
Validation: Biome passed on the two changed files, the 14 plan-usage tests passed (one new test for grouped labels reported Weekly first), and the app typecheck passed; the card was not checked visually on a desktop.

## CHG-0754 · 2026-11-26 · The Android app makes direct channels

Type: Code
Event: Delivery
Scope: Device pairing, Direct path, Android app

Summary: The Android app now moves its link to a host onto a direct WebRTC data channel, as the web app and the desktop already did, so a paired phone no longer sends every frame through the shared relay.
Hermes has no `RTCPeerConnection` and no Expo module offers WebRTC, so the app takes the class from `react-native-webrtc` 155.0.1 (MIT, over Jitsi's build of WebRTC M155, data channels only), loaded at the first try (`phoneDirect.native.ts`, `directSettingsOfLoader` in `packages/controller/src/browserLink.ts`); the web build and the desktop window are unchanged, and a build without the native module stays on the relay.
The release build needed one R8 rule for a class the library names and does not ship (`Dav1dDecoder$Natives`, an AV1 decoder the app never loads): `apps/app/plugins/withWebRtcRules.js`. Without it `assembleRelease` fails in `minifyReleaseWithR8`.
The arm64 APK grows by the library's 12.5 MB native code (`libjingle_peerconnection_so.so`), and its manifest adds a `MediaProjectionService` the app never starts (no permission); the web bundle is unchanged apart from the manifest it embeds.
The Hermes builtins guard now covers `packages/channel` too, since the phone runs its direct upgrade code for the first time.
`react-native-webrtc` pins `debug` 4.3.4, which makes `bun.lock` nest `debug` 4.4.3 under the packages that took it from the root.
Reason: The owner asked that the phone use the direct path as well (2026-11-26), after the shared relay hit its daily Durable Object cap on 2026-11-24 and a phone paired with the relay could read content but not work well.
References: [0026](../architecture-decision-record/0026-direct-webrtc-channels-with-werift-and-relay-fallback.md), amended; [device pairing](../capabilities/device-pairing/specifications.md#direct-path).
Validation: Biome and the 7-workspace typecheck passed; the full suite passed 3416 tests in 405 files (30 skipped); new tests are `directSettings.test.ts` (6) and `withWebRtcRules.test.ts` (3), the first written red. `expo prebuild` and `./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a` under JDK 17 built a 47.0 MB APK (failing first on R8, passing with the rule). On an Android 36 arm64 emulator against a disposable host on the shared relay with Cloudflare STUN: the pairing link opened the app, the host listed the device as `phone`, connected and direct with a UDP socket, a quest was created and a message answered by the fake agent, the relay counted 1 request in that minute (24 while pairing), and a force-stop and relaunch resumed the pairing and the direct channel within seconds. Not exercised: a real NAT or mobile network, the real phone, a host on another release, falling back to the relay on the phone, a long session, battery and memory cost, and the native module's behavior on iOS (no iOS build exists).

## CHG-0755 · 2026-11-26 · An empty errand a Reply opened is deleted, not archived

Type: Code
Event: Delivery
Scope: Errand controls, ArchiveThread, thread summaries

Summary: An errand that holds nothing of its own (no message, no turn, no errand beneath it) now shows the bin icon and "Delete errand" in its header and in its reply line, and ArchiveThread deletes it instead of archiving it, as an empty quest already is.
The message a Reply hangs the errand from belongs to its parent conversation, so it does not count.
`ThreadSummary.isEmpty` carries this; the pane of a deleted errand returns to its parent.
An empty quest a Reply opened from Chronicler was already deletable (`mission.isEmpty`, test in `replies.test.ts`), so no change was needed there.
Reason: The owner saw an errand opened by Reply, carrying only the anchored message at its top, offered Archive but not Delete (2026-11-26).
Validation: Biome and the workspace typecheck passed; 29 tests passed in `archivingErrands.test.ts` and `replies.test.ts` (one new test deleting an empty errand, one new assertion on `isEmpty`). Not checked in a running desktop window.
