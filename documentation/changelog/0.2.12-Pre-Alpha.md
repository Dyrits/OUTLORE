# 0.2.12-Pre-Alpha

## CHG-0782 · 2026-11-27 · The phone's Quests tab, hold, sheets and top bar follow the owner's remarks

Type: Code
Event: Delivery
Scope: Phone bar and sheets, `apps/app/src/shell`, `apps/app/src/conversation/threadPaneHeader.tsx`
Summary: The Quests tab always draws crossed swords, with a gold dot at their corner once a quest is chosen (it drew one sword before). A tab opens its sheet after a hold of a quarter of a second (half a second before). Each sheet starts with a creation row: **New realm** (the sidebar's naming dialog), **New quest** (an empty quest in the chosen realm, through `useStartQuest`, opened on success) and **New errand** (the quest's errand starter). On a quest the phone's top bar runs the desktop pane header's order: Mark as done, Archive, New quest, New errand, then the sword; New errand used to come first and New quest was missing.
Reason: The owner asked for the logo, a shorter hold, creation in every menu, and top icons that match the desktop.
References: [conversation-panes specifications](../capabilities/conversation-panes/specifications.md) (phone bar, tab and sheet bullets), [verification](../verification/2026-11-27-phone-quest-tab-and-sheets.md), CHG-0773.
Validation: Biome, the app typecheck and the app tests pass (128 files, 1,048 passed, 6 skipped); `creationOf` and the sheet's row are covered by tests shown able to fail. Not run: a phone or a window, so the dot, the hold, what pressing a row does and the top bar's order are unproven; the owner's check on a phone is the acceptance.
Evidence: the verification record above.

## CHG-0784 · 2026-11-27 · The first message of a thread draws the skills the owner named as chips

Type: Code
Event: Delivery
Scope: Thread root message, `apps/app/src/conversation/conversationEntries.tsx`
Summary: The message a thread hangs from (the pinned first message, above "1 reply") drew its text through `Markdown`, so `$debug` stayed plain words while the message box and every later message showed a chip. An owner's root now draws through `ChipText`, as the message bubble does, so skills, files, quests, errands, realms and Companions it names are chips; other senders' roots stay `Markdown`.
Reason: The owner sent `$debug` and saw the chip in the box but not in the sent message.
References: [thread-messaging specifications](../capabilities/thread-messaging/specifications.md) (a chosen skill "shows as a chip"), [verification](../verification/2026-11-27-thread-root-chips.md), CHG-0777.
Validation: Biome, the app typecheck and the app tests pass; the new test fails on the starting commit and passes on the end state. Not run: the window or a phone, so how the chip looks in the root is unchecked.
Evidence: the verification record above.
