## CHG-0509 · 2026-11-18 · Each model's context window, held to a soft limit of 272,000 tokens

Type: Code
Event: Delivery
Scope: Thread panel (context gauge), lore gauge, starting context, handover, Claude Code and Codex adapters

Summary: Redoes CHG-0501 on the current `main` (its branch and commit are lost) and adds the owner's soft limit. Each turn's stored usage records the context window its harness reported for the model (`usage.context_window`, migration `0058_usage_context_window`, additive, null for every earlier turn): Claude Code's `modelUsage[model].contextWindow` (the entry of the model that wrote the replies), Codex's `tokenUsage.modelContextWindow`. OpenCode reports none and keeps the fallback of 200,000, as does any model no harness has reported yet. The limit every reader uses is `min(reported window, 272,000)` (`contextSoftLimit`, one constant in `packages/service/src/lore/lore.ts`): a smaller window is kept, a larger one (for example 1,000,000) is held to 272,000 and the gauge says "(soft limit)". The thread's gauge, the lore gauge, the starting-context warning (and its larger-models list) and the handover allowance read it through `readContextLimit`. When a turn takes a thread's context from under the limit to at or over it, one line in the thread says so ("soft limit of 272,000 tokens; it keeps working past it") and offers the way to compact. Claude Code's `compact_boundary` event shows as "Context compacted automatically|at your request, from N tokens to M."
Reason: The owner: "Redo it. But set a soft limit for every model though, at 272K, with a warning offering compaction."
Interpretive choices (the owner can redirect any): (1) Outlore has no compaction action, so the warning's offer is a line pointing to an errand for the next part of the work, which reads the quest's journal; no compaction engine was built. (2) The line is written once per crossing (previous turn under the limit, this one at or over), not on every turn past it. (3) A model's window is the latest one reported for that model across all threads; a thread on the harness's default model (no name) takes its own latest turn's window. (4) A model with a smaller window than 272,000 is warned at its own window, without the words "soft limit". (5) The 80% and 95% bar colours apply to the effective limit. (6) For Claude Code, when the result names no entry for the reply's model, the entry used most is taken.
References: CHG-0501, CHG-0328, [thread panel, the context gauge](../capabilities/thread-panel/specifications.md#the-context-gauge), [verification](../verification/2026-11-18-context-window.md), `packages/service/src/lore/lore.ts`, `packages/service/src/work/contextWarning.ts`, `packages/service/src/harness/claudeEvents.ts`, `packages/service/src/core/recentStoreMigrations.ts`.
Validation: `bun run check` clean; `bun run typecheck` clean in all workspaces; `CI=1 bun run test`: 260 files passed, 4 skipped; 2,123 tests passed, 55 skipped. New tests: `packages/service/test/work/contextWindow.test.ts`, the Claude Code and Codex stand-in tests, the store migration test, the app's label test. ## CHG-0510 · 2026-11-18 · Signing in to a provider opens no Terminal window for Claude Code and Codex

Type: Code
Event: Delivery
Scope: Provider accounts (Sign in), the service's harness tools, the Providers section

Summary: **Sign in** no longer opens a Terminal window for Claude Code or Codex. The service runs `claude auth login` / `codex login` in the background, with the account's folder variable as before; each tool opens the browser itself and ends when the browser's answer reaches its local port (probed on 2026-11-18 with no terminal: both print their URL, Claude Code listens on a local port, Codex on 1455, and neither exits on closed or silent input). `SignInAccount` now waits for the command (ended after 5 minutes) and answers with the harnesses listed again, so the row shows the new state without Refresh; a failure shows the command's last lines. The row says "Finish signing in in your browser" meanwhile, and a second press is ignored until it ends. OpenCode's sign-in is an interactive screen and keeps its Terminal window, whose script now closes the window, by its tty through Terminal itself, only when the command exits 0, and stays open with a message on failure. The script also removes itself before it runs the command. `SignInAccount` answers null for the Terminal case, and the row then says the window closes by itself and to press Refresh. Off macOS the message with the command to run stays.
Reason: The owner: "When signing in the provider setting, a terminal pops up. Could we make that hidden, or close it automatically? Or incorporate it in a window inside the app?" The least machinery is no window at all where the tool needs none, and no new in-app terminal.
References: [provider accounts](../capabilities/provider-accounts/specifications.md), `packages/service/src/harness/harnessTools.ts`, `packages/service/src/harness/harnessCatalog.ts` (`signInNeedsNoTerminal`), `packages/service/src/work/accountsHandlers.ts`, `packages/contracts/src/requests.ts`, `apps/app/src/settings/providers.tsx`.
