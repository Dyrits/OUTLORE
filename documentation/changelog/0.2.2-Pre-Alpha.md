## CHG-0644 · 2026-11-22 · Terminals from a paired device

Type: Code
Event: Delivery
Scope: Conversation terminal

Summary: The conversation shells move from the Electron main process into the host service (ADR 0020), and every screen reaches them through the same four requests: the host's own window opens the owner's full login shell, and a paired device — a browser, or another computer's app — opens one inside the OS sandbox while the host's off-by-default **Allow terminals from paired devices** switch is on. The switch lives in the Workshop's Remote access card and changes only on the host itself; a paired device cannot turn it on, in a partial change or a full save. A paired device's shell writes only in its conversation's folder and the terminals' own temporary folder, which also holds its TMPDIR; it cannot read the Vault's folder, inherits none of the service's loopback token, and stays separate from the host window's shell of the same name, for each screen's frames carry the scope. Where no OS sandbox can run (Windows for now), terminals from paired devices stay off. The desktop's terminal bridge is gone; the packaged app's launch gate now opens its shell through the packaged service.
Reason: The owner asked to make the terminal available even for remote devices; the design was agreed on 2026-11-14 (CHG-0282, CHG-0283, ADR 0020).
References: [Conversation terminal specifications](../capabilities/conversation-terminal/specifications.md), [ADR 0020](../architecture-decision-record/0020-terminals-run-in-the-host.md), [ADR 0012](../architecture-decision-record/0012-desktop-conversation-terminals.md).
Validation: The terminal service tests (real shells, scope separation, the fenced command line, admission, the host-only switch change, sandbox requirement, folder reach) and the app tests (screen availability, session keys, the shell's frames through the client) pass. On the branch's own base, the full suite (2,764 passed, 24 skipped, 2,788 in all) passed twice; on the rebased tip, after origin's six batches landed, the full suite passes with 2,774 passed and 24 skipped (2,798 in all), with Biome and the workspace typecheck green; the pre-commit hook ran the affected suites green on commit. Not checked by hand: a paired browser against a live host, the real Seatbelt/bwrap fence on a remote shell (the tests drive a stand-in wrapper over the shared profile builder), and a packaged build's launch gate.
Open: the fenced shell's reads follow the harness sandbox (everything readable except the Vault, network open), the workable reading of ADR 0020's stricter read fence, which would strip the owner's login shell of its start-up files and installed tools; the owner kept that reading on committing (2026-11-22). The native phone app keeps no terminal surface (backlog).
Evidence: [Verification record](../verification/2026-11-22-remote-terminals.md).
