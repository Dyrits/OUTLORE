## CHG-0641 · 2026-11-22 · Provider parity registration design

Type: Documentation
Event: Agreement
Scope: Harnesses

Summary: The fourteen OpenBot provider IDs map to new harness registry entries — Hermes first, then Pi (with Inception, DeepSeek, and OpenRouter as its model groups) and Muse — plus a later custom-ACP Workshop feature. A provider enters the registry only when its adapter demonstrably mediates every sensitive action to the owner, isolates each account through its own configuration variable, and never lets Outlore read, store, or relay credentials; a provider without that proof stays blocked, its evidence recorded. Kimi (only generation 2.x, config-level yolo unproven), Grok (native subagents on in normal sessions), and Cursor and Copilot (unverified added-account isolation) stay blocked.
Reason: The owner put all providers ahead of connectors and authorized autonomous provider work.
References: [OpenBot integration parity](../research/openbot-integration-parity-2026-11-22.md).
Validation: The generic ACP model probe was verified live against Hermes 0.22.6 (initialize, session/new, model catalog) on the owner's machine. The design pins wave-1 live facts: an unconfigured Hermes home refuses sessions until repaired and given a default model, its gateway socket needs a short home path, and sign-in is an interactive terminal setup.
