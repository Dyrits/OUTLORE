## CHG-0299 · 2026-11-15 · A real dialog for Claude Code's AskUserQuestion: the thread waits for the owner's choices

Type: Code
Event: Agreement and Delivery
Scope: Action approval, contract, service, app (desktop, browser, phone)

Summary: Claude Code's `AskUserQuestion` reached the service through the permission prompt tool, `needsOf` found nothing to contain, and at the default level it ran unasked, was recorded as run automatically, and came back with `updatedInput` equal to its input and no `answers`: the owner saw no dialog and the thread went on without an answer. It is now a **choice question**. The contract gains `Choice` (header, question, options with descriptions, `multiple`, `allowsOther`), `Question.choices` and `Question.answers`, the outcomes `Answered` and `Skipped`, and the owner request `AnswerChoices` (one list of answers per choice, or null to skip). The service holds the turn in Attention with no time limit and returns the answers in `updatedInput.answers` (each question's text to the chosen labels, joined by `, ` for a multiple choice, or the typed text); Skip answers a denial telling the thread the owner chose not to answer; Stop withdraws it. Migration 0051 adds `choices` and `answers` to `questions`. The app shows one dialog per question with its choices, **Other** with a text field, **Send** (ready once every choice has an answer) and **Skip**, in the thread, in Chronicler, and on the dashboard's list, and a line says what was answered. Agreed with the owner: multiple choices and an own answer are supported, Skip is distinct from a withdrawal, only Claude Code is wired and the contract is shaped for Codex and OpenCode too.
Reason: A thread that asks the owner to choose should get the owner's choice; until now it was told yes and guessed.
References: [action approval](../capabilities/action-approval/specifications.md#choice-questions), [backlog](../backlog.md) (Codex and OpenCode), [glossary](../glossary.md) (Choice question), `packages/service/src/work/approvals.ts` (`askChoices`, `answerChoices`), `packages/service/src/policy/choices.ts`, `packages/service/src/work/threadToolHandlers.ts` (`withAnswers`), `apps/app/src/ui/questions.tsx`, `apps/app/src/ui/questionAnswers.ts`. The shape was checked against Codex 0.169.0's generated app-server types (`ToolRequestUserInput*`) and OpenCode's SDK types (`QuestionInfo`, `QuestionRequest`).
Validation: red first at the approvals seam, then green: eight tests in `approvals.test.ts` (held in Attention and listed, answers through `updatedInput.answers` with a joined multiple choice, a typed Other, an adapter asking through `askOwner`, Skip as a denial recorded apart from a withdrawal, Stop withdrawing, misfitting answers refused with the question left open, the two kinds of question not answerable by each other's request) and six new ones in `questionAnswers.test.ts` for the dialog's logic (written with the helpers, not seen red). Biome, typecheck of seven workspaces, and the full suite inside Claude Code's sandbox (1,617 passed, 54 skipped) pass. `.agents/worktree-setup.sh` now looks for the workspaces' `node_modules` in the source checkout: its glob ran in the new worktree, where nothing existed yet, so `packages/*/node_modules` was never copied.
Evidence: [Verification](../verification/2026-11-15-choice-dialog.md). Not checked: the dialog's appearance and use in a window, in a browser or on a phone (Electron cannot start inside Claude Code's sandbox, so the drive was not possible); a live Claude Code run (the fake harness stands in for the permission prompt tool, so the exact `updatedInput.answers` shape rests on Claude Agent SDK's documented format, a map from question text to the label, joined by `, ` for several); a question asked while the owner is away, then answered after a restart (a restart withdraws it as before); Codex and OpenCode, not wired.
