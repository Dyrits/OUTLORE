## Claude Code with an owner Console account

Anthropic documents non-interactive Claude Code and recommends API-key authentication when a product integrates Claude programmatically. Its legal guidance distinguishes this use from individual sign-in to an unmodified Claude Code binary. In particular, a third-party product may not route requests on behalf of users through Free, Pro, Max, or Ultra credentials. A Console API account supplies credentials in the provider's own flow and pays for usage under its Commercial Terms. The local `--bare` help confirms that OAuth and the keychain are skipped and that first-party inference uses `ANTHROPIC_API_KEY` or an explicit `apiKeyHelper`. Outlore would have to preserve its existing prohibition on collecting provider credentials. [Programmatic Claude Code](https://code.claude.com/docs/en/headless) · [Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use) · [Commercial Terms, sections A and H](https://www.anthropic.com/legal/commercial-terms) · [Outlore requirements](../requirements.md)

The candidate CLI arguments below were checked against `claude --version` and `claude --help` on 2.1.328. They are for a scoped test in a trusted empty working directory with a dedicated owner-configured Console environment and synthetic standard input. The command itself has yet to be exercised.

```sh
claude -p --bare --tools '' --disallowedTools '*' --strict-mcp-config \
  --setting-sources '' --disable-slash-commands --no-chrome \
  --settings '{"disableAllHooks":true,"disableClaudeAiConnectors":true}' \
  --no-session-persistence --output-format json --model claude-haiku-5-5
```

- `--tools ''` removes built-ins. `--disallowedTools '*'` removes all matching tools from the model's context. `--strict-mcp-config` with no MCP configuration skips discovered MCP servers. An exclusive managed MCP file makes strict mode exit at startup. [CLI reference](https://code.claude.com/docs/en/cli-reference) · [Managed MCP](https://code.claude.com/docs/en/managed-mcp#servers-passed-with---mcp-config-or---strict-mcp-config)
- `--bare` skips discovery of ordinary plugins, hooks, auto-memory, and `CLAUDE.md`. `--setting-sources ''` omits user, project and local settings scopes. Managed settings can still apply and managed policies or plugins can run hooks independently of model tools. One-run `disableAllHooks` leaves managed hooks in effect. `--no-session-persistence` prevents a resumable local session transcript. It does not control provider retention. [CLI reference](https://code.claude.com/docs/en/cli-reference) · [Settings precedence](https://code.claude.com/docs/en/settings#configuration-precedence) · [Hooks reference](https://code.claude.com/docs/en/hooks)
- Outlore's regular Claude runner registers its own MCP and approvals and enables built-in tools. A check-in would need a distinct launch path. Only an environment where managed hooks and inherited provider overrides are ruled out is a candidate. A direct stateless Claude Messages request can omit tools and MCP connectors structurally, but giving Outlore direct access to provider credentials would require a change to the current credential boundary. [Claude launch arguments at 7026ce87](../../packages/service/src/harness/claudeArgs.ts) · [Messages API](https://platform.claude.com/docs/en/api/messages/create) · [Outlore requirements](../requirements.md)

For prompts of at most 100,000 tokens, Haiku 5.5 lists $0.10 per million input tokens and $0.50 per million output tokens at standard rates. One request a day for 30 days, at 20,000 billable input and 1,000 billable output tokens each, would cost about $0.075 at those rates. CLI overhead, retries, and request count affect actual spend. The public Start-tier table lists 4,000 requests, 2 million uncached input tokens and 400,000 output tokens per minute for Haiku 5.5. That example daily workload fits the published rates. The owner's available credits, monthly spend limit, and shared rate headroom remain account-specific. Anthropic distinguishes rate limits with `retry-after` from monthly spend exhaustion. ## OpenCode with an owner-installed local model

`opencode serve --hostname 127.0.0.1 --port <private-port>` can launch a dedicated server. Use `POST /api/experimental/generate/text` on that server and require an explicit resolved local provider/model. `opencode api` also takes an operation ID or HTTP method and path, with `--server` for the target. `opencode run --standalone` is a session path. Its `--archived` option hides the created session from normal lists and leaves it persisted. The one-shot endpoint uses the server's base configuration, so its caller must supply the model explicitly to avoid taking the server's default. [OpenCode CLI](https://opencode.ai/docs/cli/) · [OpenCode API](https://opencode.ai/docs/api#generate)

Use a blank working directory outside any quest checkout and disposable XDG config, cache, data and state paths. Configure only the selected local model in the private server's base configuration. OpenCode documents `OPENCODE_DB=:memory:` for the database. A private server still applies system config and managed preferences, and those sources can install plugins. An empty project and XDG directories alone do not establish isolation from those sources. A release path needs an observable preflight for effective settings and plugins and enforcement of loopback-only network access for generation. Fail closed if the version, route, isolation or chosen model cannot be confirmed. No fallback to the owner’s shared OpenCode service or a hosted model should occur implicitly. [OpenCode configuration locations](https://opencode.ai/docs/config#locations) · [OpenCode policies](https://opencode.ai/docs/policies/) · [OpenCode CLI paths](https://opencode.ai/docs/cli/)

OpenCode supports LM Studio at `http://127.0.0.1:1234/v1`, including explicit OpenAI-compatible configuration. LM Studio can serve a downloaded model offline, and its loopback API requires no authentication by default. This path uses the owner's hardware and a model they install under its applicable license. The host must be up with sufficient memory, storage and compute. No hosted inference quota or per-token bill applies when inference is entirely local. OpenCode Console's hosted free models have their own availability, quota and data terms. Several are temporary. This research does not select or clear a hosted free model for Outlore. [OpenCode local model configuration](https://opencode.ai/docs/models/#local) · [LM Studio offline operation](https://lmstudio.ai/docs/app/offline) · [LM Studio authentication](https://lmstudio.ai/docs/developer/rest/quickstart#api-authentication) · [OpenCode Console free models](https://opencode.ai/docs/console/models/#free-models)

## Evidence and release decision

Offline, `claude --version` returned `2.1.328 (Claude Code)`. With XDG paths set to fresh temporary directories, `opencode --version` returned `opencode v2.3.0`. The `opencode run --help`, `opencode serve --help`, and `opencode api --help` calls confirmed the flags above. A binary text search for `/api/experimental/generate/text` confirmed the route literal. `command -v lms` found the LM Studio CLI. No model was started or downloaded and no inference request was made.

The requested loopback proof remains open. Nested Seatbelt setup for a network-denied process failed in this sandbox. Since the OpenCode process can load managed configuration or do background network work at startup, the CLI and binary inspections were completed without starting it as a server. To verify, run the pinned binary in a process boundary that allows only loopback egress, start a mock OpenAI-compatible decoder on loopback, and configure only that stub as a local model in the private OpenCode server. Record one request using synthetic quest text. Assert that the provider request carries only the intended messages and exposes no tools, query the server's session list before and after to confirm no session is created, and check that an unavailable model fails without fallback. Verify that a marker plugin or MCP server in the owner's usual config did not start. Use a real owner-installed local model only after the mock passes, to check classification quality with synthetic reportable and quiet cases.

Choose the private OpenCode v2 local path only after those checks and with explicit acceptance of the experimental API dependency. If that path cannot be isolated, the remaining decisions are whether to restrict a Claude CLI release to verifiably isolated, owner-configured Console environments or approve a dedicated inference path with a revised credential boundary. The scheduler and Missive delivery can be verified independently against a stand-in Companion. [Check-in specification](../capabilities/background-check-ins/specifications.md)
