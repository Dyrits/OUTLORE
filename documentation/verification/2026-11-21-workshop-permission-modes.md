# Verification: one permission vocabulary in the Workshop and the composer

- **Work:** CHG-0617, on `worktree/workshop-permissions` (worktree `.worktrees/workshop-permissions`). Recorded results below come from this session's runs on 2026-11-21; the Workshop page and the composer were not seen in a window.
- **What the change is:** the Workshop's Permissions page offers the four permission modes (Supervised, Auto-accept edits, Auto, Full access) as the default every thread without its own mode runs with; the composer's "Default permissions" names the chosen default; the two approval levels and the separate sandbox-escape toggle are gone, with Full access now covering leaving the sandbox; a thread cannot change the default (`change_setting` refuses it). A store migration (`0071_settings_permission_mode`) translates a saved store's choices: Also commands and edits → Supervised, Sensitive actions only → Auto, the escape setting on → Full access (except beside Also commands and edits, which becomes Supervised).
- **Amendment, same day:** every composer now offers the selector — a quest's and an errand's, in the host window and on a paired phone (the mode request left the host-only list) — and the mode changes at any time, like the runner: `SetThreadPermissionMode` no longer refuses during a running turn; the turn's admitted mode (`0072_turn_permission_mode` snapshots it into the turn row) holds until the turn ends, and the next turn applies the new mode. A turn admitted before the snapshot falls back to the thread's and the Workshop's current choice.
