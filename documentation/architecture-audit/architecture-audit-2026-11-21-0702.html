A1 · A pane-session reducer behind the hook

Strong in-process

apps/app/src/shell/usePaneChain.ts (138) · paneHost.tsx (258) · paneChain.ts (202 — deep, tested) · no usePaneChain test exists

Before — five effects, rendering-only

After — one thick band of pure logic

Problem: the pane session's transitions are a state machine living inside a React hook — shallow: an interface of 19 values hiding five effects, each bug of the fold/reveal/starter class visible only by rendering (the starter-carryover comment at usePaneChain.ts:60-68 is this class, patched in place).

  • locality: fold/reveal/starter interplay in one module
  • interface shrinks to state + dispatch; implementation absorbs the effects
  • tests: starter carryover and chronicle-target classes become plain Node tests
  • deletion test passes: the logic concentrates in the reducer

Top recommendation

C1 — the inbox declares the wake

It is the only candidate that closes a silent failure mode, not just a shape: a forgotten wake compiles and passes every test, and the message sleeps in an idle quest with no sweep to rescue it. The predicate that makes it cheap already exists (isPendingDeliveryOf — CHG-0608 built it for exactly this kind of rule), the wake is already a no-op with nothing deliverable, and the commands seam keeps its pinned order and its tests untouched. Sixteen call sites learn one interface; one test then covers every sender the rule exists for.

Runner-up: B1, the chronicleTarget module — the newest rule in the app (CHG-0608, e4ace28f), already three matching copies and one SQL re-derivation deep in drift; every future Chronicle feature builds on where a target points.
